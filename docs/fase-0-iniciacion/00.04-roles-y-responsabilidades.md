## Objetivo
Separar roles de ejecucion del proyecto de los roles operativos del sistema
para no mezclar gobierno del brownfield con permisos de producto.

## Roles de ejecucion
| Rol | Responsabilidad principal |
|---|---|
| Sponsor / duenio de negocio | Prioriza inversion, alcance y decisiones comerciales irreversibles. |
| Product / operacion | Define backlog, valida flujos reales y decide que ya representa al negocio vivo. |
| Arquitectura | Cuida limites del monolito modular, integraciones y reglas de cambio tecnico. |
| Backend | Implementa y mantiene dominios, API, persistencia y jobs. |
| Frontend | Mantiene storefront y backoffice alineados al flujo real del negocio. |
| QA | Verifica flujos criticos, regresion y evidencia de cierre. |
| Infra / release | Protege deploy, backup, rollback y estabilidad operativa. |
| Documentacion | Consolida la capa canonica y preserva trazabilidad entre docs vigentes y nuevos artefactos. |

## Matriz minima de responsabilidad
| Decision | A | R | C | I |
|---|---|---|---|---|
| Vision y alcance | Sponsor / Product | Product | Arquitectura, Documentacion | QA, Infra |
| Roadmap del producto | Product | Product | Sponsor, Arquitectura | Equipo tecnico |
| Arquitectura y despliegue | Arquitectura | Backend, Infra | Product | QA, Documentacion |
| Cierre de evidencia QA | QA | QA | Frontend, Backend, Product | Sponsor |
| Homologacion documental | Documentacion | Documentacion | Product, Arquitectura | Equipo tecnico |

## Roles operativos del sistema
| Rol del sistema | Uso principal |
|---|---|
| `super_admin` | Configuracion critica, auditoria y soporte avanzado. |
| `admin` | Operacion transversal del negocio. |
| `operador_pagos` | Revision de comprobantes y contexto de pedidos. |
| `ventas` | Catalogo comercial, promociones, leads mayoristas y seguimiento. |
| `marketing` | CMS, promociones, segmentos, campanas y contenido. |
| `seller_manager` | Onboarding de vendedores, reglas de comision y liquidaciones. |
| `vendedor` | Consulta de ventas atribuidas, comisiones y payout. |
| `cliente` | Cuenta, pedidos, direcciones, puntos y compra. |

## Regla de separacion
- Los roles de ejecucion gobiernan como se cambia el repo.
- Los roles del sistema gobiernan quien puede hacer que dentro del producto.
- Ninguna decision de permisos reemplaza la necesidad de RACI sobre roadmap,
  arquitectura, QA o release.
