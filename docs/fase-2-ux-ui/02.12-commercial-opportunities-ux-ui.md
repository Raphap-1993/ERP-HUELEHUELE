# Fase 2 - Commercial Opportunities UX/UI

## Objetivo

Formalizar la UX operativa del slice `013-commercial-opportunities` como una
capa puntual de negociacion dentro de `/crm`, separando visualmente el caso
general del cliente de la oportunidad concreta sin abrir una app nueva ni
romper la continuidad del workbench comercial.

## Superficies

### Superficie principal

- detalle del cliente dentro de `/crm`
- sigue mostrando el resumen general del `customer_relationship_case`
- suma un bloque especifico de `commercial_opportunity`
- el bloque de oportunidad no reemplaza el resumen del caso
- separa negociacion puntual de relacion comercial general

### Superficie secundaria

- bandeja filtrada de oportunidades dentro de `/crm`
- lectura de deals activos y cerrados sin salir del mismo modulo
- no abre ruta aparte ni kanban nuevo
- no vende un CRM enterprise separado

## Contrato UX visible minimo

- el detalle del cliente debe distinguir claramente:
  - resumen general del caso
  - bloque puntual de oportunidad
- la oportunidad visible expone:
  - etapa propia
  - `expectedValue`
  - `currency`
  - `targetCloseAt`
  - `commercialOwner`
  - `assignee`
  - `commercialChannel`
  - `opportunityType`
  - `lostReason` cuando aplique
- la oportunidad tiene timeline propio
- la oportunidad tiene tareas propias minimas
- el caso general del cliente conserva su propio timeline y tareas

## Elementos visibles clave

- badge o selector de etapa de oportunidad
- resumen de valor esperado y fecha objetivo de cierre
- owner y assignee del deal
- canal y tipo del deal
- rail o zona de referencias principal/secundarias
- timeline puntual del deal
- tareas minimas del deal
- lectura clara de cierre `won` y `lost`
- lectura clara de reapertura desde `lost`

## Lecturas secundarias o derivadas

- si no existe oportunidad activa, el detalle del cliente debe poder mostrar
  estado vacio o CTA para abrir/converter
- la bandeja puede filtrar por etapa, owner, assignee, canal, tipo y estado
  de cierre
- la relacion entre oportunidad y caso padre puede leerse como contexto, pero
  no como una sola timeline mezclada
- referencias secundarias ayudan a leer quote, order, lead o evidencia sin
  prometer un document hub nuevo

## Guardrails UX

- el slice vive dentro de `/crm`; no abre modulo separado
- la oportunidad no debe sentirse como reemplazo del caso transversal
- la UI no debe mostrar probabilidad de cierre ni forecast
- la UI no debe sugerir multiples oportunidades activas por caso
- la UI no debe mezclar timeline del caso con timeline del deal
- la UI no debe vender automatizacion fuerte del lifecycle

## Regla UX critica

- el usuario debe entender que sigue operando el mismo cliente canonico dentro
  de `/crm`, pero ahora con una capa puntual de negociacion concreta y valor
  esperado
- la oportunidad debe leerse como un deal especifico dentro del caso, no como
  todo el CRM comercial del cliente

## Criterio de cierre

- `013` queda documentado como una extension puntual del workbench del cliente
- el detalle del cliente y la bandeja secundaria de `/crm` quedan defendidos
  como las unicas superficies necesarias del corte
- la separacion entre caso general y deal puntual queda explicitada sin abrir
  modulo nuevo
