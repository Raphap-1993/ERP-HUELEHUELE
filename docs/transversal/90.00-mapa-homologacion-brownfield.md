# Mapa De Homologacion Brownfield

[README principal](../../README.md) | [Indice docs](../README.md)

## Objetivo
Definir como `ERP-HUELEHUELE` adopta la capa canonica de
`project-templatev12.104.0` sin borrar la documentacion operativa que hoy
explica el producto vivo.

## Contexto real
- El software ya opera con `apps/web`, `apps/admin`, `apps/api` y `apps/worker`.
- La documentacion vigente esta repartida por tema: producto, arquitectura, flujos, infra y una serie previa `docs/00-06`.
- Esta homologacion agrega una capa canonica por fases; no reescribe la historia del repo ni invalida evidencia util.

## Reglas de transicion
- No se elimina documentacion previa en esta etapa.
- Cada artefacto canonico nuevo declara que fuentes vigentes consolida.
- Si un tema ya tiene artefacto canonico y este cubre el mismo alcance, el canonico pasa a ser la entrada principal y el documento previo queda como evidencia.
- Si un tema todavia no tiene artefacto canonico, sigue mandando la documentacion vigente actual.

## Resultado de este corte
- La raiz ya tiene `AGENTS.md`, `AI_CONTEXT.md`, `PROJECT_MAP.md`, `TRACEABILITY_MATRIX.md` y `GLOSSARY.md`.
- Ya existen `docs/fase-0-iniciacion/` a `docs/fase-8-operacion/` como capa canonica intermedia.
- `specs/001-checkout-payments/` fija la primera feature real homologada.
- `specs/002-vendors-commissions/` fija el segundo slice brownfield homologado del canal seller-first.
- `specs/003-wholesale-leads-quotes/` fija el tercer slice brownfield homologado para mayoristas y distribuidores.
- `specs/004-loyalty-points-redemptions/` fija el cuarto slice brownfield homologado para programa de puntos y canjes operativos.
- `specs/005-cms-content-blocks-marketing-surfaces/` fija el quinto slice brownfield homologado para CMS/editorial y superficies de marketing content as-is.
- `specs/006-campaigns-marketing-automation/` fija el sexto slice brownfield homologado para campaigns, catalogos read-only y frontera de dispatch desacoplada.
- `specs/007-customers-identity-conflicts/` fija el septimo slice brownfield homologado para maestro de clientes, conflictos de identidad y merge operativo as-is.
- `specs/008-crm-stage-order-follow-up/` fija el octavo slice brownfield homologado para `crmStage`, `commercialTrace` y el seguimiento derivado del pedido as-is.
- `specs/009-crm-manual-ampliado/` fija el noveno slice brownfield homologado para el workbench manual de seguimiento sobre pedidos ya elegibles.
- `specs/010-crm-transversal-por-cliente/` fija el decimo slice brownfield homologado para el workbench comercial transversal sobre cliente canonico.
- La documentacion vigente previa sigue siendo necesaria para otros frentes del monorepo que aun no tienen slice canonico propio, especialmente pipeline comercial amplio, scoring y automatizaciones posteriores al CRM transversal por cliente.
