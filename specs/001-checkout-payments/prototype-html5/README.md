# Prototype HTML5 - Checkout Payments

## Estado

No aplica como artefacto nuevo en este corte.

## Razón

El checkout ya existe como runtime vivo en `apps/web`. La homologación brownfield usa ese runtime como evidencia principal en lugar de duplicarlo en un HTML5 estático.

## Regla futura

Si se aprueba un rediseño mayor del checkout o de la experiencia de pagos, esa iniciativa sí debe abrir un prototipo HTML5 o equivalente formal antes de pasar a construcción.
