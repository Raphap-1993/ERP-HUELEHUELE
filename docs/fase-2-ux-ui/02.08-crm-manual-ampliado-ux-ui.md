# Fase 2 - CRM Manual Ampliado UX/UI

## Objetivo

Formalizar la UX operativa vigente o esperable del workbench manual sobre
pedidos dentro de `Pedidos > Operacion`, sin convertirlo en CRM por cliente
ni mezclarlo con fulfillment, dispatch o campaigns.

## Fuentes de runtime

- `apps/admin/app/pedidos/page.tsx`
- `apps/admin/components/orders-workspace.tsx`
- `apps/admin/lib/api.ts`
- `apps/api/src/modules/orders/orders.controller.ts`
- `apps/api/src/modules/orders/orders.service.ts`
- `packages/shared/src/types/api.ts`

## Superficies

### `Pedidos > Operacion`

- sigue siendo la superficie operativa principal del slice
- conserva `SummaryTile`, `OperationGuideCard` y `CommercialTraceCard` como
  baseline del seguimiento derivado
- abre un bloque principal adicional para el `order_follow_up_case`
- no se convierte en CRM general ni en bandeja separada de ventas

### Workbench manual del caso

- muestra `assignee`
- muestra `status`
- muestra `nextStep`
- muestra `followUpAt`
- muestra timeline manual simple
- muestra tareas opcionales
- debe convivir con el bloque de trazabilidad derivada del pedido

### Bandeja filtrada dentro de `Pedidos`

- muestra por defecto casos `open` y `waiting_customer`
- permite filtrar `resolved` y `cancelled`
- no abre una nueva aplicacion ni un dashboard global

## Contrato UX del slice

- `Ventas` necesita ver rapido quien lleva el caso, que sigue y cuando toca
  volver a actuar
- el caso manual complementa el seguimiento derivado del pedido, no lo
  reemplaza
- el timeline es operacional, no conversacional ni cliente-centrico
- las tareas ayudan a operar, pero no convierten la vista en task manager

## Guardrails

- no abrir timeline por cliente
- no abrir mensajeria CRM real
- no abrir dashboard separado
- no mezclar fulfillment, dispatch ni vendedor
- no romper la primacia de `Pedidos > Operacion` como detalle del pedido

## Regla UX critica

- el usuario debe entender que esta operando un caso manual sobre un pedido
  ya elegible
- `nextStep` y `followUpAt` deben sentirse como disciplina minima del caso
- la UI no debe vender el slice como CRM amplio ni como pipeline comercial
  general

## Criterio de cierre

- el workbench manual queda documentado como extension natural del tab
  `Operacion`
- la bandeja filtrada secundaria queda defendida dentro del mismo modulo de
  `Pedidos`
- el slice deja explicito que el runtime no es CRM por cliente ni mensajeria
  comercial
