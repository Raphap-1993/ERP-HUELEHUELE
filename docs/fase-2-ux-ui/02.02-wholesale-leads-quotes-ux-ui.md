# Fase 2 - UX/UI Wholesale Leads Quotes

## Objetivo

Formalizar la UX del funnel mayorista vigente sin convertir la homologacion en
un portal B2B autoservicio ni en un frente de polish visual fuera de alcance.

## Fuentes de runtime

- `apps/web/components/account-workspace.tsx`
- `apps/admin/lib/api.ts`
- `docs/flows/wholesale-flow.md`
- `docs/flows/commercial-accesses.md`

## Superficies

### Formulario publico mayorista / distribuidores

- captura interes comercial y contacto
- debe sentirse como puerta de entrada a un proceso comercial asistido
- no debe parecer alta inmediata ni login B2B

### Backoffice de leads y cotizaciones

- superficie operativa principal de `Ventas`
- aqui viven calificacion, deduplicacion, cotizacion, seguimiento y cierre
- debe sentirse como workbench comercial, no como checkout ni como CRM
  enterprise completo

### `/cuenta`

- sigue siendo la entrada autenticada unica
- el resumen mayorista es una vista secundaria dentro de la cuenta
- no debe parecer panel mayorista operativo ni portal autoservicio

## Contrato UX del slice

- `wholesale` y `distributor` deben leerse como variantes del mismo funnel
- el lead publico no promete acceso inmediato
- `Ventas` si ve seguimiento, estados y contexto comercial
- el usuario autenticado solo ve un resumen comercial basico, no herramientas de
  operacion

## Regla UX critica

- una cotizacion `accepted` no debe sentirse como pedido ni como acceso ganado
- el acceso mayorista solo debe aparecer cuando la relacion queda `won`
- `/cuenta` no debe sugerir que el usuario puede autogestionar cotizaciones,
  precios o condiciones mayoristas

## Criterio de cierre

- las superficies mayoristas quedan nombradas y delimitadas
- el contrato UX no contradice el funnel vigente
- Fase 3 puede heredar esta lectura sin reabrir el diseno del producto
