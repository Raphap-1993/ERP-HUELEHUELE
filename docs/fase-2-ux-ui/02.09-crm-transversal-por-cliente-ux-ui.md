# Fase 2 - CRM Transversal Por Cliente UX/UI

## Objetivo

Formalizar la UX operativa vigente o esperable del workbench comercial por
cliente dentro de `/crm`, sin convertirlo en pipeline comercial amplio ni
mezclarlo con campaigns, scoring o identidad canonica.

## Fuentes de runtime

- `apps/admin/app/crm/page.tsx`
- `apps/admin/components/crm-workspace.tsx`
- `apps/admin/lib/api.ts`
- `apps/api/src/modules/customers/customers.controller.ts`
- `apps/api/src/modules/customers/customers.service.ts`
- `packages/shared/src/types/api.ts`

## Superficies

### Detalle del cliente en `/crm`

- sigue siendo la superficie operativa principal del slice
- conserva perfil, direcciones y pedidos recientes como baseline del cliente
- abre un resumen comercial corto adicional para el
  `customer_relationship_case`
- no se convierte en pipeline comercial amplio ni en app separada

### Workbench transversal del cliente

- muestra `commercialOwner`
- muestra `assignee`
- muestra `status`
- muestra `classification`
- muestra `origin`
- muestra `nextStep`
- muestra `followUpAt`
- muestra timeline transversal
- muestra tareas opcionales
- debe convivir con referencias read-only a pedidos y a casos `009`

### Bandeja filtrada dentro de `/crm`

- muestra por defecto casos `open` y `waiting_customer`
- permite filtrar `dormant` y `resolved`
- no abre una nueva aplicacion ni una ruta separada

## Contrato UX del slice

- `Ventas` necesita ver rapido quien lleva la relacion comercial con el
  cliente y que sigue
- el caso transversal complementa `007` y `009`, no los reemplaza
- el timeline es comercial y contextual, no transaccional completo
- las tareas ayudan a operar, pero no convierten la vista en un task manager
  general

## Guardrails

- no duplicar toda la historia de pedidos
- no abrir pipeline comercial amplio
- no abrir scoring o automatizacion dura
- no abrir mensajeria real
- no sacar el workbench fuera de `/crm`

## Regla UX critica

- el usuario debe entender que esta operando la relacion comercial de un
  cliente canonico
- `nextStep` y `followUpAt` deben sentirse como disciplina minima del caso
- la UI no debe vender el slice como campaigns, pipeline ni CRM corporativo
  mas grande de lo que hoy existe

## Criterio de cierre

- el workbench transversal queda documentado como extension natural del
  detalle de cliente
- la bandeja filtrada secundaria queda defendida dentro del mismo modulo
  `/crm`
- el slice deja explicito que el runtime no es campaigns, scoring ni
  pipeline comercial amplio
